# Архитектура BracketLab CS2

## Модель турнира

`src/tournament.rs` и `Tournament.kt` содержат одинаковые правила формирования основных форматов. Источник позиции матча содержит UUID команды, ссылку на победителя или проигравшего более раннего матча либо BYE. Rust проверяет зависимости через petgraph. Kotlin проверяет порядок ссылок при импорте и разрешает позиции в порядке матчей. Геометрия хранится отдельно.

Обе реализации используют посев по степеням двойки для сеток на вылет. Для Double Elimination проигравшие из верхней сетки переходят в нижнюю, а повторный гранд-финал открывается при победе нижнего финалиста в первой серии. GSL содержит пять матчей. Round Robin распределяет пары по турам методом вращения. Таблица сортируется по победам, поражениям и выбранному дополнительному критерию. Swiss формирует пары по текущим результатам, ограничивает поиск неповторяющихся пар и назначает BYE участнику с наименьшим числом таких проходов среди нижних позиций. При исчерпании поиска допускаются повторные пары.

Для жеребьёвки обе платформы используют SplitMix64 и Fisher–Yates с отбрасыванием значений, которые вносили бы смещение при взятии остатка. Закреплённые позиции исключаются из перемешивания внутри корзины. В проекте сохраняются полученный порядок и seed последнего автоматического перемешивания. Ручная правка порядка сбрасывает seed. При создании групп порядок из предпросмотра распределяется змейкой по группам.

Результат хранит счёт серии, карты, технический статус и примечание. BYE вычисляется из позиции. Изменение результата отклоняется, если оно поменяет участников сыгранного матча, повлияет на сформированный следующий тур Swiss или поменяет состав уже связанного этапа. Квалификация ссылается на предыдущие этапы и число проходящих из каждого. Порядок в целевом этапе можно перемешивать и редактировать без потери привязки.

## Данные

Windows использует rusqlite со встроенной SQLite и SQL-миграциями из `migrations`. Android использует Room, корутины и StateFlow. В Windows ревизии и журнал принадлежат отдельным турнирам, у каждого есть указатель текущей ревизии. Отдельная запись хранит выбранный турнир. Запись, смена указателя и журнал действия выполняются в одной транзакции вне потока интерфейса. Undo и Redo сохраняются после перезапуска. Новый ввод после Undo создаёт новую ветку и прекращает последовательность Redo.

JSON версии 1 является форматом обмена. Обе платформы используют стабильные UUID команд. Логотип переносится как PNG в Base64, размер миниатюры ограничен 96 пикселями по длинной стороне при добавлении. SQLite-файлы платформ имеют собственные схемы и используются локально. Приложение работает без сетевого доступа. У Android нет разрешения `INTERNET`.

## Отображение и экспорт

Windows использует eframe/egui с wgpu, Inter и Phosphor. Модель сцены рассчитывает высоту карточек по числу строк карт и строит кривые kurbo в мировых координатах. R-tree отбирает карточки по видимой области. Переходы между полосами Double Elimination идут по межколоночным коридорам. SVG растрируется resvg через usvg и tiny-skia на отдельном потоке.

Android использует Compose Material 3, Compose Canvas, DataStore для настройки движения и Coil для предпросмотра логотипа в редакторе. Матчи рисуются через Android Canvas. PNG строится из той же геометрии вне viewport. Обе платформы проверяют размер растрового буфера перед выделением памяти.

На Windows анимируются наведение, вписывание сетки и продвижение результата. Анимация читает состояние матча после транзакции. Android использует Compose Animation для переходов состояния поля. Подробности визуальной проверки и ограничения описаны в [сценариях проверки](qa.md).
