# Сценарии проверки

## Фактически проверено

- Windows Release x64 собран. 10 тестов Rust прошли, включая проверку геометрии и все размеры сеток на вылет от 2 до 64 команд.
- Android Debug и Release собраны. 8 JVM-тестов Kotlin прошли. Подпись установочного APK проверена через apksigner.
- На эмуляторе Android API 35 через интерфейс добавлены четыре команды, проведена жеребьёвка, сыграны полуфиналы и финал. Финал сохранился после переустановки поверх текущей версии и после повторного запуска. Экспортированный PNG содержит все три встречи и их результаты.
- В Windows запущено нативное окно с wgpu, открыта карточка матча, создан и проверен PNG для каждой сцены. Перенос между платформами проверен на уровне формата JSON и общих тестовых данных.

## Воспроизводимые изображения

Запустите `bracketlab.exe --fixtures dist/scenes`. Команда пишет PNG и редактируемый JSON каждой сцены.
Для скриншота приложения выполните `bracketlab.exe --capture dist/screen.png dist/scenes/single-16.json`. Четвёртый аргумент задаёт индекс этапа с нуля. Для просмотра плей-офф в сцене с группами используйте индекс 4.

| Сцена | Файлы |
| --- | --- |
| Single Elimination, 5 команд | `single-05` |
| Single Elimination, 16 и 64 команды | `single-16`, `single-64` |
| Double Elimination, 8 команд | `double-08` |
| GSL, 4 команды | `gsl-04` |
| Round Robin, 7 команд | `league-07` |
| Swiss, 16 команд | `swiss-16` |
| Четыре GSL-группы и плей-офф | `groups-playoff` |
| Открытый плей-офф с двумя результатами | `preview-08` |

## Приёмка

1. Создайте турнир на четыре команды. Загрузите широкий логотип PNG и игрока. Проведите жеребьёвку с закреплённой позицией. Вручную поменяйте посев.
2. Создайте Single Elimination. Введите результаты полуфиналов, проверьте состав финала, завершите финал и откройте таблицу.
3. Попробуйте изменить победителя сыгранного полуфинала. Операция должна быть отклонена. Снимите результат финала и измените полуфинал. Проверьте Undo, Redo и журнал.
4. Создайте четыре группы GSL по четыре команды, завершите их и передайте две команды из каждой в плей-офф. Смена состава прошедших команд после создания плей-офф должна отклоняться.
5. Переместите и приблизьте сетку. Экспортируйте PNG всего турнира и отдельно раунда. Откройте PNG и проверьте крайние карточки, кириллицу, логотипы и счёт.
6. Закройте и снова откройте приложение. Проверьте сохранённый счёт. Экспортируйте JSON, откройте его на другой платформе и сравните участников и результаты.
7. На Android повторите жесты и проверьте диалоги на портретном экране. На Windows повторите проверку в оконном режиме.

## Ограничения

- В Android между полосами Double Elimination переходы подписаны в карточках. Windows рисует линии между полосами.
- SQLite хранит полные ревизии проекта. Размер истории растёт с количеством изменений.
- Поиск пар Swiss ограничен по числу попыток. На сложных раскладках пары могут повторяться.
- Встроенной замены жеребьёвки уже начатого этапа нет. Новая жеребьёвка создаёт отдельный этап. Импорт современного проекта и перенос между платформами идут через JSON.
- Заявленные 60 FPS, работа на физических Android-устройствах и уровень визуального качества 10/10 не подтверждены.
